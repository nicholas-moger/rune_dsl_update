# demo-harness-codegen — the fork code-generation driver

`org.finos.rune.demo:demo-harness-codegen:1.0.0` · main class `demo.harness.codegen.Main` ·
Java 21.

Runs the **fork** (rune-dsl-plus) parser + Java generator over the vendored demo corpus, and
dumps the spotlight model as fork IR and as a raw AST tree. Speaks the CONTRACTS.md §3
`##DEMO##` protocol on stdout and reports the §4 `codegen` metrics.

The **legacy (upstream Xtext 9.83.0)** driver is a separate module: [`legacy/`](legacy/).

---

## Build and run

There is no aggregator pom; build each module directly.

```
mvn -f demo/harness/codegen/pom.xml -Dmaven.repo.local=demo/work/.m2 package
java -cp "demo/harness/codegen/target/classes;demo/harness/codegen/target/lib/*" \
     demo.harness.codegen.Main <verb> ...
```

Dependencies are **copied** to `target/lib/`, never shaded — uniform with the legacy module,
where shading is actively harmful (it collapses the Eclipse stack's per-jar
`plugin.properties`). Use `;` as the classpath separator on Windows, `:` on POSIX.

## Verbs

### `generate`

```
generate --mode m1|m2|m3
         --src "dir;dir;..."         # corpus source roots, walked recursively
         --builtins <dir>            # basictypes.rosetta + annotations.rosetta
         --out <dir>                 # output root; files land at <out>/<package path>/<Name>.java
         [--filter drr|all]          # default: all
         [--receipt <file>]          # optional; see "Receipts" below
         [--command "<exact line>"]  # verbatim command string for the receipt
```

Loads every `.rosetta` under the builtins directory and then under each `--src` root (sorted,
recursive), links them as **one workspace** via `RWorkspace.build(...)`, and runs the full
generator set per model:

```
ModelObjectGenerator -> ChoiceObjectGenerator -> RuleGenerator -> ReportGenerator
                     -> DataRuleGenerator     -> LabelProviderGenerator
```

then a single whole-workspace `FunctionGenerator.generateWithErrors(...)` pass. This wiring is
copied verbatim from `ArgumentPositionRuleWrapSeatTest.generateCell(...)` in
`rune-java-generator`, which is the in-repo reference for "generate one cell the way the
regression gate does".

Files are written with their generated bytes **verbatim** — no newline translation — so the
tree is byte-comparable against the legacy tree by `demo/build/diff-trees.ps1`.

**Filters.** `drr` keeps only namespaces `drr` / `drr.*`. `all` keeps everything except
`com.rosetta.model` and `com.rosetta.test.model` (CONTRACTS §1). Independently of the filter,
`GeneratorModel.shouldGenerate` drops the builtin FILES by name
(`basictypes.rosetta`, `annotations.rosetta`, `model-no-code-gen.rosetta`) — the same set
upstream's `RosettaGenerator` ignores.

**Errors.** Every generator returns `List<GenerationException>`; they are all collected. If any
element errored, the run prints one `##DEMO## {"ev":"error",...}` per failure (first 10) plus a
summary line, writes **no files**, and exits `3`. For the demo corpus (the drr-6.34.1 closure)
zero errors are expected.

### `ir-dump`

```
ir-dump --src <spotlight .rosetta> --builtins <dir> --outJson <file> --outText <file>
        [--receipt <file>] [--command "<exact line>"]
```

Parses the spotlight file **together with the builtins** (so `[metadata key]` and the basic
types resolve), adapts the spotlight model with `AstToIRAdapter.adaptModel(...)`, then writes:

- `--outJson` — `IRJsonSerializer.toJson(List<IRNode>)`, i.e. the **versioned document**
  `{"irFormatVersion":1,"nodes":[...]}`. This is the schema Lane D's emitters consume; it is
  not the bare single-node fragment that the `toJson(IRNode)` overload produces.
- `--outText` — `IRPrinter.printAll(List<IRNode>)`.

The Phase-1 adapter covers **data types, choices and enums**. Functions, rules, reports and
type aliases return empty and are absent from the dump by design; the run says so on stdout
when the adapted-node count is lower than the root-element count.

### `ast-dump`

```
ast-dump --src <spotlight .rosetta> --builtins <dir> --out <file>
         [--receipt <file>] [--command "<exact line>"]
```

Compact recursive JSON of the parsed `RModel` tree, for the dashboard's AST diagram:

```json
{"astDumpVersion":1,"source":"period.rosetta","maxDepth":12,"nodes":N,"truncatedAt":N,
 "root":{"kind":"RModel","name":"...","fields":{...},"children":[ ... ]}}
```

Depth is capped at 12; a node at the cap carries `"childrenTruncated": N` instead of children.
Traversal uses the typed `RNode.children()` contract. **Scalar fields are harvested by
reflection** over public no-arg accessors returning a string, primitive, boxed primitive, enum
or `Optional` of one, sorted by name so the output is deterministic. Any accessor that throws
is skipped — a diagram must not be able to fail a demo run — so a field may be *absent*, never
wrong.

## Modes m1 / m2 / m3 — selected OUTSIDE this code

`--mode` is a **label** carried into the metrics so a receipt can never be attributed to the
wrong route. The route itself is chosen by the outer command line, because
`rune-java-generator` reads the flags through `IRGeneration` (`ServiceLoader` + system
property) rather than through any generator API:

| mode | JVM flag | extra jar required on the classpath |
|---|---|---|
| `m1` | *(none)* | — (the standard Path-1 route) |
| `m2` | `-Drosetta.generator.ir=true` | `org.finos.rune:rune-ir-java:0.0.1-SNAPSHOT` |
| `m3` | `-Drosetta.generator.ir.optimised=true` | `org.finos.rune:rune-ir-java-optimised:0.0.1-SNAPSHOT` |

Verified against `rune-java-generator/.../spi/IRGeneration.java` (`PROPERTY` /
`OPTIMISED_PROPERTY`, both read with `Boolean.getBoolean`, so the spelling must be `=true`) and
the two `META-INF/services/` registrations in `rune-ir-java` / `rune-ir-java-optimised`.

Three behaviours worth knowing before wiring `demo/runs.json`:

1. **Setting both flags throws**, on every call — the routes are exclusive by design.
2. **A flag on with no matching provider on the classpath does NOT fail.** It prints one
   `System.err` notice and silently runs Path-1. If an m2/m3 receipt looks identical to m1,
   check that the route jar was actually on the classpath.
3. **More than one registration of the same provider throws** — do not put two copies of a
   route jar on the classpath.

Because the two providers register under different service files, m2's and m3's jars can both
be present at once; only the flag decides. Example:

```
java -Drosetta.generator.ir=true \
     -cp "target/classes;target/lib/*;<rune-ir-java jar>" \
     demo.harness.codegen.Main generate --mode m2 ...
```

## Protocol and metrics

`##DEMO##` events per CONTRACTS §3: `start`, `metric`, `progress` (emitted every 250 written
files, plus once at the end), `done`, `error`. Every protocol line is flushed immediately.
All output is ASCII — non-ASCII characters are `\uXXXX`-escaped.

Final `done` metrics for `generate` (CONTRACTS §4 `codegen` keys first, measured extras after):

```
mode, files, wallMs, jvmStartToFirstFileMs, exit,
filter, sourceFiles, generatedModels, parseMs, linkMs, generateMs, writeMs
```

- `wallMs` = JVM start (`RuntimeMXBean.getStartTime()`) to last file written. It **includes JVM
  boot**, which is deliberate: that is what makes it comparable with the legacy leg.
- `jvmStartToFirstFileMs` = JVM start to the moment the first generated file lands on disk.
- **`peakRssMb` is deliberately absent.** CONTRACTS §4 assigns it to the outer PowerShell
  wrapper (`PeakWorkingSet64`); this process cannot observe its own peak working set without
  guessing, and §2 forbids fabricating a field.

## Receipts

`--receipt <file>` makes the runner write a CONTRACTS §2 receipt itself. It records only what
it measured. `command` is taken verbatim from `--command` when given — pass the exact line from
`demo/runs.json`, since §8 requires the two to be equal — otherwise this process's own argv is
re-quoted as a best-effort stand-in.

## Exit codes

| code | meaning |
|---|---|
| 0 | success |
| 2 | usage error (unknown verb, missing/invalid flag) |
| 3 | the run produced generation errors, or the spotlight model was not found |
| 4 | unexpected failure (stack trace on stderr, `##DEMO## error` on stdout) |

## Why the legacy driver is a separate module

The fork and upstream `rune-lang:9.83.0` **both own the Java package
`com.regnosys.rosetta.*`** with incompatible class shapes — verified: `parser`, `rosetta`,
`types`, `utils` and `validation` sub-packages exist in both `rune-parser:0.0.1-SNAPSHOT` and
`rune-lang:9.83.0`. Putting both on one classpath is the documented failure recorded in
`scripts/xtext-oracle/pom.xml` (`IncompatibleClassChangeError` at Guice graph construction).
The two drivers therefore have disjoint dependency sets and are launched separately.

`rune-java-generator` pulls `org.finos.rune:rune-runtime:9.83.0` transitively — that is the
generated-code *runtime* (`com.rosetta.model.*` plus `model/*.rosetta`), not the language jar,
so it introduces no collision.
